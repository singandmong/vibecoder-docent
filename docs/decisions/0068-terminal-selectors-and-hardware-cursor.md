# 0068 — 터미널은 진짜 커서를 입력 위치에 두고, 세션과 대화를 검색되는 선택창으로 고른다

Date: 2026-10-15
Status: Accepted. 사용자 요청. ADR 0038의 선택 목록, ADR 0039의 `@ # $` 입력창 목록, ADR 0049의 그리기 방식을 고친다.

## Context

사용자가 터미널 클라이언트(`docent-tui`)의 문제 네 가지를 알렸다.

1. 세션은 고를 수 있지만 질문할 대화(카드)를 고르기 어렵다. 세션을 고르면 곧장 세션 전체 대화로 들어가고, 카드는 `#`나 Ctrl+T를 알아야 열린다. 대화 목록에는 제목 한 줄과 시각뿐이라 무엇을 고르는지 알 수 없고, 웹처럼 고른 카드의 내용이 보이지 않았다.
2. 한글 입력이 느리고 영문 입력 상태로 보인다.
3. 웹에는 있는데 터미널에는 없거나 구조가 다른 기능이 많다.
4. 세션 선택창과 옵션창에서 검색, 선택, 이동이 어렵다. OMP를 따라 달라.

조사한 사실:

- 한글 입력이 느린 것은 계산 때문이 아니다. 그리기는 글자 하나에 약 15ms(16ms 프레임 묶음)였다. 가장 유력한 원인은 진짜 터미널 커서다[INFERENCE: 실제 입력기에서 재현하지 못함]. 도슨트는 `ESC[?25l`로 커서를 숨기고 가짜 막대(`▏`)를 글자 사이에 끼워 그렸으며, 프레임마다 마지막으로 쓴 줄 끝에 커서가 남았다. 터미널은 한글을 조합하는 글자(IME 사전 입력)와 후보 창을 *진짜 커서 위치*에 붙인다. 그래서 조합 중인 글자가 엉뚱한 자리에 뜨거나 안 보이고 확정 뒤에야 나타나 느리게 느껴질 수 있다. 입력기의 한/영 상태 표시는 터미널 앱이 정하므로 도슨트가 바꿀 수 없다.
- Pi 터미널 라이브러리(`@earendil-works/pi-tui`)의 Editor는 커서 자리에 `CURSOR_MARKER`를 넣고 TUI가 그 위치로 진짜 커서를 옮긴다("IME 후보 창 위치"). 사용자의 OMP 설정은 `showHardwareCursor: true`("Show terminal cursor for IME support")다. 반전된 가짜 커서 칸은 그대로 함께 그린다.
- 웹의 카드 제목과 3문장 요약 계산(`summarySentences`, `attachCardAnswer`)은 `index.html` 안에만 있었다. 웹은 새 카드가 위, 세션 전체 대화 버튼이 따로, 세션을 열어도 카드나 스레드를 자동으로 열지 않는다.
- 터미널 전체 점검 결과는 `docs/terminal-parity-plan.md`에 있다.

## Decision

1. **진짜 커서.** 매 프레임 끝에 커서를 입력 위치(입력창 캐럿, 선택창이 열려 있으면 그 검색창의 캐럿)로 옮기고 보이게 한다(`ESC[row;colH`, `ESC[?25h`). 프레임을 쓰는 동안에는 숨겨 깜빡이지 않게 한다. 입력 위치에는 반전된 칸(색을 못 쓰면 `▏`)을 함께 그린다. 줄바꿈은 글자 단위 배치(`layoutDraft`)로 계산하고 커서 칸은 줄 끝에서 한 칸 더 갈 수 있다. `DOCENT_HARDWARE_CURSOR=0`이면 커서를 숨긴 채 위치만 옮긴다.
2. **선택창.** `@`(세션), `#`(대화), `$`(설정)를 입력창 첫 글자로 치면 글자는 입력되지 않고 선택창이 열린다. Ctrl+P, Ctrl+T, Ctrl+O, Ctrl+G와 같은 창이다. `/` 명령 목록만 입력창 아래의 OMP식 인라인 목록으로 남긴다. 선택창은 입력창 자리까지 쓰고 위에서부터 가로선, 제목, 검색창, 목록, 고른 항목의 미리 보기, 도움말과 `순번/전체`, 가로선이다. 글자(한글 포함)는 검색창으로 가서 공백으로 나눈 낱말이 모두 들어간 항목만 남기고(이름에 든 낱말을 먼저, 같은 점수는 받은 순서), 위아래는 한 칸씩(끝에서 반대편으로), PgUp/PgDn은 한 화면씩(끝에서 멈춤), Enter/Tab은 고르기, 첫 Esc는 검색어 지우기, 다음 Esc는 닫기다. 설정창의 깊이, 미리 설명, 모델은 고른 뒤에도 열려 있고 체크 표시만 옮겨 간다. `@ # $`로 시작하는 질문은 앞에 공백을 두고 쓴다(ADR 0039의 "Esc로 기호를 질문 글자로 남김"은 `/`에만 남는다).
3. **세션 → 대화 흐름.** 세션을 고르면 곧바로 그 세션의 대화 선택창이 열린다(프로필만 바꿀 때는 열지 않는다). 목록은 세션 전체 대화, 사건 카드(웹처럼 새것이 위), 카드에 없는 저장 대화 순이다. 카드 한 줄은 `[질문|작업 결과|계획]`, 제목, 오른쪽에 ★, `NEW`(가장 새 비과거 카드 하나), 설명 중·미리 설명 중·한도, 문답 수, 시각이고 둘째 줄이 요약이다. 제목과 요약은 웹과 같은 규칙이라 `summarySentences`와 `cardDisplay`를 `conversations.mjs`로 옮기고 웹도 그것을 쓴다. 답이 없는 카드의 요약은 선택지, 없으면 AI가 한 말의 앞부분이다. 처음에 고르는 항목은 설명 중인 대화, 없으면 가장 새 카드, 없으면 세션 전체 대화이며, 사용자가 움직이거나 거르기 전까지 카드가 새로 오면 따라간다. 고른 항목의 내용(카드의 AI 출력 Markdown, 최근 문답)이 목록 아래에 미리 보인다. Enter로 열면 대화 화면 맨 위에 `[분류] 제목`과 돌아가는 키가 보이고, 입력창이나 대화에서 Esc를 누르면(완성 목록과 바로잡기 모드가 없을 때) 대화 선택창이 지금 대화를 고른 채 열린다.
4. **현재 상태에 맞춘 기본값.** 세션 선택창은 지금 대화 중인 세션, 없으면 지금 작업 폴더(`process.cwd()`)를 포함하는 세션을 먼저 고르고(Herdr 우선 목록 순서는 서버가 정한 그대로), 세션의 폴더, 시작·마지막 시각, SSH 별칭, 처음 요청, 최근 작업을 미리 보여 준다. 서버가 미리 설명을 붙인 새 카드는 웹처럼 같은 requestId로 붙어(`attachAuto`) 끝나면 저장된 문답을 다시 불러온다.
5. **즐겨찾기.** `POST /api/favorites`를 터미널에서도 쓴다(`transport.setFavorite`). Ctrl+F, `/즐겨찾기`, 선택창의 Ctrl+F. 화면에 먼저 반영하고 실패하면 되돌린다.

## Consequences

- 새 모듈 `app/terminal-select.mjs`(거르기, 스크롤, 선택창 그리기)와 `terminal-input.mjs`의 `layoutDraft`, `editLine`이 상태 없이 시험된다. `terminal-ui.mjs`의 인라인 목록은 `/` 명령만 맡는다.
- 한글을 조합하는 글자가 입력 위치에 뜨는지는 터미널과 입력기가 정한다. 이 저장소의 시험은 프레임에 쓴 커서 위치와 보임을 확인한다. 실제 한글 입력기(macOS 한국어 2벌식)를 Herdr, Ghostty 같은 터미널에서 눌러 보는 확인은 사용자가 한다. Herdr가 안쪽 창의 커서를 바깥 터미널로 넘기는지는 이 저장소에서 검증하지 못했다.
- 터미널 시험 도구의 가상 화면이 커서 위치를 따라가고, 시험 도우미는 세션을 고른 뒤 대화 선택창을 한 번 더 지나간다.
- 서버, 웹 화면 모양, 설명 API는 바뀌지 않는다. 웹의 카드 제목과 요약은 같은 규칙을 공용 함수로 쓰게 됐을 뿐이다.
- 영향 범위: `app/terminal-ui.mjs`, `app/terminal-select.mjs`, `app/terminal-input.mjs`, `app/conversations.mjs`, `app/transport.mjs`, `app/index.html`(공용 함수 사용), `tests/terminal.test.mjs`, `tests/terminal-select.test.mjs`, `tests/conversations.test.mjs`, `README.md`, `bin/docent-tui.mjs`.
