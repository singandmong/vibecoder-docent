# 0049 — 터미널 명령은 한글과 영문을 함께 쓰고, 화면은 바뀐 줄만 다시 그린다

Date: 2026-10-12
Status: Accepted. 사용자 요청. ADR 0038의 Composer와 ADR 0039의 `/` 명령 목록을 고친다.

## Context

1. `/` 명령 목록은 `/종료`처럼 한글 이름만 보여 줬다. 영문 별칭(`exit`)은 숨은 검색어라 쓸 수 있는지 알 수 없었다.
2. 터미널 화면이 느리다는 보고가 있었다. 표본 세션(저장된 답 26개)으로 재 보니 Node 안의 그리기 비용은 글자당 5~7ms였지만, 글자 하나를 칠 때마다 화면을 모두 지우고(`ESC[2J`) 전체 줄을 다시 썼다. 120x45 창에서 6KB, 220x60에서 13KB였다. 그리기는 항상 35ms 뒤로 미뤄져 키 하나에 약 40ms가 걸렸다. 설명 중에는 스피너가 1초에 10번 전체 화면을 다시 쓰면서 매번 모든 답의 Markdown을 새로 그렸다(답 26개 기준 한 번에 약 20ms). Herdr 같은 멀티플렉서와 터미널은 이 출력을 모두 다시 그려야 한다.

## Decision

1. 명령은 `/종료 (exit)`처럼 한글과 영문 이름을 함께 보여 준다. `/종료`, `/exit` 모두로 고르고 실행한다. 이름이 입력한 글자로 시작하는 명령을 먼저 보여 준다(`/s`는 세션, 설정이 앞). 영문 이름: session, thread, answers, settings, refresh, steer, stop, exit.
2. 처음 그릴 때, 화면 크기나 줄 수가 바뀔 때만 화면 전체를 다시 그린다. 그 밖에는 직전에 쓴 줄과 비교해 바뀐 줄만 커서 이동, 서식 초기화, 줄 지우기 뒤에 다시 쓴다. 동기화 출력(`ESC[?2026h`)으로 묶어 깜빡이지 않게 한다.
3. 그리기는 입력 직후 바로 하고, 설명 스트림이나 스피너처럼 잦은 갱신만 16ms에 한 번으로 묶는다.
4. Markdown 그리기 결과를 글과 너비별로 기억한다(최대 400개). 같은 답을 다시 그릴 때 다시 계산하지 않는다.

## Consequences

- 글자 하나에 화면으로 나가는 양이 6~13KB에서 0.1~0.2KB로 줄었다. 연속 입력의 반응 시간은 약 40ms에서 16ms 이하가 됐다.
- 다른 프로그램이 같은 창에 글을 쓰면 다음 전체 그리기(창 크기 변경) 전까지 그 자리가 남을 수 있다. 도슨트 화면은 전용 대체 화면(`ESC[?1049h`)을 쓰므로 일반적으로 생기지 않는다.
- 테스트의 가상 화면은 전체 프레임과 줄 고침을 모두 반영한다.
- 영향 범위: `app/terminal-ui.mjs`, `tests/terminal.test.mjs`, `README.md`.
