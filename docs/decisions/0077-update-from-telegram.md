# 0077 — 텔레그램에서 새 버전 받기

Date: 2026-11-25
Status: Accepted (주인 결정 2026-11-25). [0072](0072-update-from-release.md) 결정 4(설치는 이 컴퓨터에서만)에 좁은 예외를 둔다. [0076](0076-telegram-resident-bot.md)의 봇 범위는 그대로 유지한다.

## 문제

[0072](0072-update-from-release.md)로 화면, 터미널, CLI에서 새 버전을 받을 수 있게 됐다. 하지만 서버를 켠 컴퓨터 앞에 앉아야 설치할 수 있다. 주인이 휴대폰 텔레그램으로 도슨트를 쓰는 동안에는 새 버전이 나왔는지 알 길이 없고, 알아도 컴퓨터로 돌아가야 한다. 주인은 텔레그램에서 새 버전을 알려 받고 버튼 하나로 올리기를 원한다.

걸림돌은 세 가지다.

1. 0072 결정 4는 설치 요청을 loopback 주소로 온 요청에만 허용한다. 인증이 없는 서버가 원격 요청으로 코드를 바꾸지 않게 하려는 규칙이다. 텔레그램 버튼을 위해 HTTP 경로를 열면 이 규칙이 깨진다.
2. 0076은 봇이 설명만 하고 명령을 실행하지 않는다고 못박았다. 설치는 새 코드를 받아 프로세스를 다시 켜는 일이라 그 선과 맞닿는다.
3. 설치가 끝나면 서버가 스스로 끝나므로 봇도 같이 멈춘다. 주인은 결과를 알 수 없다.

## 결정

1. **알림과 버튼만 둔다.** 봇은 새 버전을 알리고 `[설치하고 다시 시작]` 버튼과 `/update` 명령을 준다. 자동 설치는 하지 않는다. 설치는 주인이 누를 때만 일어난다.
2. **확인 주기.** 봇은 시작 60초 뒤에 한 번 확인하고, 그 뒤 24시간마다 확인한다. 같은 버전은 한 번만 알린다. 알린 버전은 기억해 두고, 더 새 버전이 나오면 다시 알린다.
3. **서버 안 설치 함수를 직접 부른다.** 봇은 0072의 설치 함수를 서버 프로세스 안에서 직접 부른다. HTTP `/api/update`는 지금처럼 loopback 요청만 받고 새 경로도 만들지 않는다. 이것이 0072 결정 4의 좁은 예외다. 짝지은 텔레그램 주인의 버튼만 해당하고 다른 어떤 경로도 열지 않는다.
4. **보안 근거.** 버튼을 누를 수 있는 사람은 짝지은 주인 한 명뿐이다. 설치 대상은 공식 저장소의 최신 정식 릴리스와 그 sha256으로 고정돼 있고, 봇은 주소나 해시를 받지 않는다. 텔레그램 계정을 빼앗겨도 공격자가 할 수 있는 일은 공식 릴리스 재설치와 재시작까지다. 사용자의 코드와 파일은 고치지 않는다.
5. **누를 때 다시 확인한다.** 버튼은 눌린 순간 최신 버전을 다시 확인하고, 알림에 적힌 버전과 같을 때만 설치한다. 그 사이 더 새 버전이 나왔으면 설치하지 않고 실제 최신 버전을 알려 준다. 이미 설치 중이면 겹쳐 설치하지 않는다.
6. **버전 기억과 재시작 뒤 보고.** 봇은 지금 실행 중인 버전을 상태 파일에 기억한다. 시작할 때 기억한 버전이 실행 중인 버전과 다르면 누가 올렸든(봇 버튼, 웹, 터미널, CLI) "도슨트 버전이 바뀌었어요: vA → vB"를 보낸다. 버전이 같은데 설치 전에 남긴 "올리는 중" 표시가 이 버전에서 설치를 시작했다고 말하면 "v… 설치가 끝나지 않았어요"라는 실패 알림을 보내고 맥에서 `docent doctor`로 확인하라고 안내한다. 두 경우 모두 처리한 뒤 표시를 지운다. 기억한 버전이 아예 없는 첫 시작은 기록만 하고 보내지 않는다. 설치하기 전에 "올리는 중" 표시를 파일에 먼저 남긴다.
7. **맥북은 안내만 한다.** 봇은 맥미니 한 곳에서만 돌므로 맥북은 직접 올리지 않는다. 설정된 peers의 `/api/health`로 버전만 읽어 `/status`와 새 버전 알림에 보여 준다. 그 컴퓨터의 버전이 최신 릴리스보다 낮으면 그 컴퓨터에서 `docent update`를 하라고 안내한다(단지 다르다는 이유로는 안내하지 않는다). 읽지 못하면 모른다고 적는다.
8. **새 버전이 켜지지 않으면 봇도 멈춘다.** 새 버전 서버가 뜨지 못하면 봇도 같이 멈추므로 보고를 보낼 수 없다. 이 경우 설치 전에 보낸 안내 문장 "5분이 지나도 소식이 없으면 맥에서 docent doctor 로 확인해 주세요"로 알려 주는 데서 그친다. 감시 프로세스와 자동 되돌리기는 두지 않는다. 새 상주 프로세스를 늘리지 않는다는 0076 결정 2를 지킨다.
9. **실기기 확인은 0.33.1로 한다.** 0.33.0은 이 기능이 들어간 첫 릴리스라서 그 자체로는 알림을 받을 수 없다. 그다음 릴리스인 0.33.1을 내서 휴대폰에서 알림, 버튼 설치, 재시작 뒤 보고를 확인한다.

## 결과

- 주인은 컴퓨터 앞이 아니어도 새 버전을 알아채고 한 번의 버튼으로 맥미니를 올린다. 설치 방법과 검증(공식 릴리스, sha256, npm 전역 설치만)은 0072와 같다.
- 0072의 loopback 제한은 HTTP에서 그대로 유지된다. 예외는 서버 안에서 봇이 같은 함수를 부르는 한 경로뿐이고, 호출할 수 있는 사람은 짝지은 주인이다.
- 맥북은 따로 올려야 한다. 봇이 버전 차이를 알려 줄 뿐이다.
- 새 버전이 시작하지 못하면 사용자가 직접 복구해야 한다. 이 위험은 받아들인다. 되돌리기 장치를 두는 일은 새 상주 프로세스가 필요해 지금은 하지 않는다.
- 버전이 바뀌지 않았고 "올리는 중" 표시도 없는 재시작은 아무 말도 하지 않는다. 어떤 경로로 올렸든 버전이 바뀌면 한 번 알린다.
