# 0069 — 모델을 고르지 않으면 세션의 모델로 설명하고, 모델 선택 후보는 범위로 좁힌다

Date: 2026-10-15
Status: Accepted. 사용자 요청. ADR 0016의 1항("값이 없으면 omp 기본 모델")을 바꾼다. 나머지 항은 그대로다.

## Context

프로필의 도슨트 모델이 비어 있으면 설명과 학습 분류가 omp 기본 모델로 돌았다. 사용자는 기본을 "대화에 연결된 모델 그대로"로 하고, 나머지 모델은 선택 후보 범위를 정할 수 있게 해 달라고 했다. 물어서 정한 뜻은 둘이다.

- 기본 모델 = 설명 대상 **세션의 모델**(작업 기록의 마지막 모델). 이미 시작한 도슨트 스레드의 모델 유지가 아니다.
- 범위 = omp의 scoped models처럼 **선택 후보 범위**. 모델을 어디에 쓰는지의 범위가 아니다.

조사한 사실: 세션 어댑터는 이미 전사에 `(모델: X)` 표식을 쓴다(omp `model_change`, Claude와 Codex의 메시지 모델). omp의 표식은 `공급자/id`(예: `anthropic/claude-sonnet-5-5`), Claude와 Codex는 id만 적는다. omp 카탈로그는 모델마다 `공급자/id` selector를 가진다.

## Decision

1. `profile.model`이 null이면 설명 요청이 시작될 때 세션 전사의 마지막 `(모델: X)` 표식을 카탈로그의 정확한 모델 하나로 바꿔 쓴다(`app/session-model.mjs`). 정확히 일치하는 selector, `:high` 같은 추론 접미를 뗀 selector, 같은 id, Claude의 날짜 붙은 id(`-YYYYMMDD`를 뗌) 순으로 찾는다. 같은 id가 여러 공급자에 있으면 세션 호스트의 공급자(claude는 anthropic, codex는 openai-codex, openai)가 하나로 가려질 때만 고르고, 아니면 고르지 않는다. 추측하지 않는다.
2. 표식이 없거나 카탈로그에서 못 찾으면 omp 기본 모델로 설명한다. 실패가 아니라 대체가 아니다. 이 경우를 `answer.modelSource: "default"`로 남기고, 설정 화면과 답의 메타 줄이 "omp 기본 모델 (세션 모델을 알 수 없음)"이라고 보인다. 찾은 모델은 `"session"`, 프로필에서 고른 모델은 `"profile"`이다. 옛 답에는 이 필드가 없다.
3. 찾은 세션 모델의 실행이 실패하면 ADR 0016 4항대로 다른 모델로 바꾸지 않고 오류를 알린다. 프로필에서 고른 모델은 세션 모델보다 우선한다. 한 요청 안에서 분류와 설명은 같은 모델을 쓰고, 스레드 대화는 모델이 바뀌면 새 대화가 된다(키에 selector가 이미 있다).
4. `GET /api/session-model?id=`는 `{raw, model}`을 돌려준다(`raw`는 전사의 표기, `model`은 카탈로그의 `{selector, provider, name, cost}` 또는 null). 웹 설정과 터미널 상태줄이 쓴다. 카탈로그 조회는 60초 캐시하고, 읽지 못하면 이전 값, 없으면 빈 목록이라 omp 기본 모델로 간다. 모델 목록 API(`/api/models`)와 프로필 모델 검증은 캐시하지 않는다.
5. 프로필에 `modelScope`를 둔다: 카탈로그의 정확한 selector 목록(중복 제거, 500개 이하) 또는 null(전체). 빈 목록은 null로 저장한다. 카탈로그에 없는 selector가 있으면 400이다. 옛 프로필은 null로 읽는다. 범위는 모델 선택 목록만 좁히며, 지금 고른 모델은 범위 밖이어도 목록에 남긴다. 설명에 쓰이는 모델과 세션 모델 규칙에는 영향이 없다.
6. 화면. 웹: 모델 탭의 기본 항목이 "세션의 모델 (기본)"이고 현재 모델 줄에 지금 세션의 모델이 보이며, "모델 범위"에서 제공자별 체크 목록으로 정하고 저장, 해제한다. 터미널: `$` 설정의 기본 항목이 "세션 모델 (기본)", 모델 목록은 범위로 줄고, "범위 정하기"는 모델을 Enter로 담고 빼는 선택창을 열어 맨 위(검색해도 남는) "범위 저장"으로 저장한다. 상태줄의 모델은 고른 모델, 없으면 세션 모델 이름이다.

## Consequences

- 설명을 만드는 모델이 세션과 같아져 세션이 쓰는 모델에 따라 설명 비용이 달라진다. 비용을 줄이려면 설정에서 저렴한 모델을 직접 고른다(ADR 0016).
- 세션의 모델이 omp에 인증되어 있지 않으면 설명이 실패할 수 있다. 그때는 설정에서 다른 모델을 고르면 된다.
- Gemini와 pi 세션은 호스트 공급자 우선순위가 없어 같은 id가 여러 공급자에 있으면 omp 기본 모델로 간다.
- 다른 컴퓨터(peer)의 세션도 전사의 표식으로 같은 규칙을 쓰며, 모델은 이 컴퓨터의 omp 카탈로그에서 찾는다.
- 영향 범위: `app/session-model.mjs`, `app/ask.mjs`, `app/learning.mjs`, `app/store.mjs`, `app/server.mjs`, `app/transport.mjs`, `app/index.html`, `app/terminal-ui.mjs`, `app/terminal-select.mjs`, 시험, `README.md`, `docs/architecture.md`.
