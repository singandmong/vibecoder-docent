# 0075 — 요청 출처 확인과 동시 실행 상한

Date: 2026-10-18
Status: Accepted

## 문제

2026-10-18 보안 점검에서 남긴 것들(1차·2차 보고서: `docs/security/`). 본문 형식과 다른 컴퓨터 응답 검증은 [0074](0074-local-api-json-only-and-peer-response-checks.md) 에서 정했다.

1. Host 를 보지 않아, 다른 사이트가 DNS 를 자기 도메인으로 돌린 뒤(DNS 재바인딩) 브라우저로 이 서버의 세션 목록·전사·문답을 그대로 읽을 수 있었다.
2. 브라우저가 붙이는 출처 표시(`Sec-Fetch-Site`)를 쓰지 않아 CSRF 에 한 겹이 비어 있었다.
3. 실시간(SSE) 구독이 연결마다 감시기와 1초 폴링을 만들었고 수 제한이 없었다. 17개부터 503 을 내려던 앞선 시도는 헤더를 이미 보낸 뒤 예외를 던져 **서버 프로세스를 끝냈다**(개발계에서 확인).
4. 설명 요청과 모델 호출에 상한이 없어, 몰려든 요청이 전사 읽기·분야 판정·모델 호출을 한꺼번에 만들었다.

## 결정

1. **Host 검사.** loopback 이름(`127.0.0.1`, `localhost`, `::1`), 설정한 host, 이 컴퓨터의 사설·테일넷 주소(`10/8`, `172.16/12`, `192.168/16`, `100.64/10`, `169.254/16`, `127/8`, `::1`, `fc00::/7`, `fe80::/10`), `*.ts.net`, `*.local` 만 받는다. 아니면 403. 재바인딩은 공인 이름으로 오므로 여기서 막힌다. 모바일 PWA 는 테일스케일 Serve 를 거쳐 Host 가 `*.ts.net` 이거나 loopback 이라 그대로 동작한다.
2. **출처 표시.**
   `Sec-Fetch-Site: cross-site` 인 요청은 403. 같은 출처(우리 화면·PWA), 주소를 직접 연 경우(`none`), 브라우저 밖 클라이언트(표시 없음)는 그대로 받는다.
3. **실시간 구독 공유와 상한.** 감시기는 세션마다 하나를 두고 구독자에게 나눠 준다(화면 구독과 미리 설명이 같은 감시기를 쓴다). 한 세션 16, 전체 128개를 넘으면 **스트림을 열기 전에** 503. 헤더를 보낸 뒤 생긴 오류는 상태 코드를 바꾸지 않고 연결만 닫는다.
4. **설명 작업 상한.** 동시에 도는 설명 작업은 8개(`MAX_JOBS`)까지. 나머지는 전사 읽기와 분야 판정 전에 순서를 기다리고, 기다리다 중단하면 대기에서 빠진다(`app/capacity.mjs`).

## 결과

- 개발계(임시 HOME, 가짜 omp)에서 확인한 것:
  - Host: `evil.example`, `attacker.test`, `example.com` 403. `127.0.0.1`, `localhost`, 이 컴퓨터의 테일스케일 주소(`100.x.x.x`), 사설망 주소(`192.168.x.x`), 테일스케일 이름(`<기기>.ts.net`) 200.
  - 같은 세션의 17번째 실시간 구독 503, 여러 세션 합계 129번째 503, 서버는 계속 살아 있음.
  - 동시 설명 12개 모두 200, 동시에 도는 생성은 4개(살아 있는 대화 상한 `MAX_LIVE`)까지.
  - 웹 화면(세션 10개 표시, 콘솔 오류 없음)과 터미널 질문·답이 그대로 동작.
- 시험: `tests/server-guards.test.mjs`, `tests/live-share.test.mjs`, `tests/capacity.test.mjs`. 전체 `node --test` 226개 통과.
- 점검에서 낸 나머지 항목: `DOCENT_UPDATE_API`(시험용 릴리스 주소 바꾸기)는 그대로 둔다. 그때도 sha256 검사는 유지되고, 주소 검사만 시험을 위해 건너뛴다.
