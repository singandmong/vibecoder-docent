# 0072 — 화면에서 새 버전 받기

Date: 2026-10-18
Status: Accepted

## 문제

새 버전을 쓰려면 사용자가 릴리스 주소를 찾아 `npm install -g`, 서버 재시작, 터미널 다시 열기를 직접 해야 했다. 웹(PWA 포함), 터미널, CLI 어디서든 같은 방법으로 원격의 새 버전을 받아 적용하기를 원했다.

## 결정

1. **받을 곳은 하나.** GitHub `singandmong/vibecoder-docent` 의 최신 정식 릴리스(`releases/latest`)와 그 안의 `vibecoder-docent-<버전>.tgz` 만 쓴다. 초안과 시험판은 무시한다. 버전은 숫자로 비교하고 더 새것일 때만 제안한다.
2. **확인 후 설치.** GitHub 가 알려 준 파일의 sha256(`digest`)과 내려받은 파일이 같을 때만 설치한다. 다운로드 주소가 이 저장소의 릴리스 경로가 아니면 설치하지 않는다. `npm install -g --prefix <설치된 곳> --ignore-scripts` 로 지금 설치된 위치에 덮어쓴다.
3. **설치하는 주체는 서버.** `POST /api/update {apply:true}` 가 받고, 설치하고, 자기 자신을 끝낸다. launchd/systemd 같은 관리자가 있으면(`XPC_SERVICE_NAME`, `INVOCATION_ID`) 관리자가 새 파일로 다시 띄우고, 없으면 떨어진 프로세스가 잠시 뒤 `docent start` 로 다시 켠다.
4. **이 컴퓨터에서만.** 설치 요청은 loopback 주소로 온, Host 와 Origin 이 loopback 인 요청만 받는다. 테일스케일로 연 휴대폰 PWA나 다른 기기는 새 버전을 확인하고 알림만 본다. 서버를 연 컴퓨터에서 설치해야 한다(인증이 없는 서버가 원격 요청으로 코드를 바꾸지 않게).
5. **npm 전역 설치만.** 패키지 위치가 `<prefix>/lib/node_modules/vibecoder-docent` (Windows 는 `<prefix>\node_modules\...`)일 때만 설치한다. 저장소에서 실행하면 `git pull`, macOS 앱은 앱을 다시 설치하라고 이유를 보여 준다.
6. **화면마다**
   - 웹/PWA: 설정 > 연결 > "업데이트" 카드의 "새 버전 확인"과 "설치하고 다시 시작". 설치 뒤 서버 버전이 바뀌면 화면을 새로고침한다. 15초마다 서버 버전을 보고 화면보다 새것이면 왼쪽 아래에 "새 버전 vX 적용" 버튼(새로고침)을 보인다.
   - 터미널: `/업데이트 (update)` 는 서버에 설치를 맡기고, 새 서버가 뜨면 같은 세션으로 이 터미널을 새 파일로 다시 연다. `/재시작 (restart)` 는 업데이트 없이 다시 연다. 서버가 터미널보다 새 버전이면 알림 줄에서 `/재시작` 을 권한다. 다시 여는 일은 `bin/docent-tui.mjs` 가 같은 실행 파일을 다시 띄워서 한다(실행 중인 모듈은 바꿔 끼울 수 없다).
   - CLI: `docent update [--check]`. 서버가 켜져 있으면 서버에 맡기고 새 버전이 뜰 때까지 기다린다. 꺼져 있으면 직접 설치한다.
7. 새 버전 확인은 5분 동안 기억한다. `DOCENT_UPDATE_API` 는 시험에서만 릴리스 주소를 바꾸며, 그때는 다운로드 주소 검사를 건너뛴다.

## 결과

- 2026-10-18 맥미니에서 처음 화면 업데이트를 했을 때 설치는 바로 끝났지만 launchd 가 다시 켠 서버가 몇 분 동안 응답하지 않았다. 그동안 Time Machine 네트워크 백업이 복사 중이었고, 서버의 libuv 작업 스레드가 파일 `open()` 에서 멈춰 있었다. 같은 서버를 셸이나 임시 launchd 작업으로 켜면 바로 떴다. 그래서 새 서버를 5분까지 기다리고, 관리자가 켜는 중이면 "docent start"가 아니라 기다리라고 안내한다.
- `docent install-omp` 는 업데이트가 다시 실행하지 않는다. omp 확장이나 코어 프롬프트 설치 형식이 바뀐 릴리스는 CHANGELOG 에 다시 실행하라고 적는다.
- 맥북처럼 PATH 의 `docent` 와 서비스가 쓰는 `docent` 가 다른 곳에 설치된 경우, 서버가 자기 설치 위치에 설치하므로 서비스 쪽이 맞게 올라간다. 셸의 `docent --version` 은 그대로일 수 있다.
- 서비스 관리자가 없는 Windows 의 `docent start` 서버는 떨어진 프로세스로 다시 켠다. 이 경로는 CI 에서 확인하지 않았다.
