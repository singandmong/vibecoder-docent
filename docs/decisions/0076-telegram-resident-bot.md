# 0076 — 텔레그램 상주 도슨트 봇

Date: 2026-11-24
Status: Accepted (주인 결정 2026-11-24). [0014](0014-learning-evidence-and-pip.md) §웹앱과 PiP의 "사용자 표면은 웹앱만. Hermes/Telegram은 계획에서 제외한다"를 대체한다. [0063](0063-pre-explanation-off-by-default.md)(미리 설명 기본 꺼짐)은 유지한다.

"하지 않는 것"의 명령 실행 금지에 대한 예외: 주인 버튼으로 공식 릴리스 업데이트와 재시작만 한다(ADR 0077). 사용자의 코드와 파일은 여전히 고치지 않는다.

## 문제

도슨트는 화면을 열어야만 쓸 수 있다. 코딩 에이전트가 사용자에게 묻거나 일을 끝냈을 때 주인이 자리를 비우면 카드가 쌓여도 모른다. 주인은 텔레그램을 일상적으로 쓰므로, 같은 서버의 설명을 휴대폰 개인 채팅에서 주고받고 새 카드를 알려 받고 싶어 한다.

걸림돌은 세 가지다.

1. ADR 0014가 메신저 표면을 계획에서 뺐다. 이후 [0037](0037-mobile-terminal-and-macos.md)이 웹, PWA, 터미널, macOS로 표면을 넓히며 "같은 서버 하나" 원칙을 세웠고, [0005](0005-surface-local-web-app.md)는 메신저를 "웹앱 위에 얹는다"고 남겼다. 표면을 여는 결정이 따로 없다.
2. 새 상주 프로세스나 의존성을 늘리면 설치 안내([0041](0041-agent-install-onboarding.md))의 서비스 등록 금지, 의존성 0 정책과 부딪친다.
3. 텔레그램 요청 주소에 토큰이 들어 있어, 오류 문구나 로그에 주소를 그대로 넣으면 토큰이 샌다.

## 결정

1. **텔레그램 개인 채팅만.** 채널은 텔레그램 하나다(D6). 디스코드는 Gateway(WebSocket)를 직접 구현해야 하고 초안도 없어 범위 밖이다. 카카오톡은 공식 챗봇에 채널과 공개 스킬 서버 URL, 5초 응답 제한이 필요하고 개인 계정 자동화는 공식이 아니라서 제외한다. 그룹과 채널 메시지는 무시한다(D4). 웹훅, 공개 엔드포인트, Tailscale Funnel도 쓰지 않는다. 받는 방식은 `getUpdates` 롱 폴링이다.
2. **서버 안 module.** 봇은 도슨트 서버 프로세스 안의 module이다. 새 상주 프로세스, 새 launchd 잡, 새 npm 의존성(텔레그램 SDK 포함)이 없다. Bot API는 Node 내장 `fetch`로만 부른다(D1). 어떤 오류에도 서버 프로세스를 끝내지 않는다. 맥미니 한 곳에서만 돌리고, 맥북 세션은 peer(`@book/…`)로 따라간다(D9).
3. **토큰은 환경변수만.** `DOCENT_TELEGRAM_TOKEN`으로만 받고 config.json에 쓰지 않는다. 오류, 로그, `/api/bot` 응답에 토큰도 토큰이 든 URL도 넣지 않는다. 토큰이 없으면 봇 코드는 시작하지 않는다(D3). 도슨트 전용 새 봇을 쓴다. 샤를 봇과 한 토큰을 같이 쓰면 두 소비자가 업데이트를 서로 가져간다. 노출된 샤를 토큰은 이 결정과 무관하게 교체하지 않으며 위험을 알린 뒤 주인이 정한다(D10). 설치 안내(INSTALL-AGENT.md)에는 봇 질문을 넣지 않는다. 봇 생성은 주인이 손으로 하고 설치 에이전트는 비밀값을 받지 않는다([0041](0041-agent-install-onboarding.md) §3). 안내는 README에만 둔다(D11).
4. **짝짓기 코드와 주인 한 명.** 처리 조건은 config.json `telegram.owner`(정수)가 `message.from.id`와 같고 `chat.type`이 `private`일 때뿐이다. 콜백 버튼도 `callback_query.from.id`로 같은 검사를 한다(D4). 주인 연결은 `docent telegram pair`가 `DOCENT_HOME/telegram-pair.json`(0600, `{code, expiresAt}`, 코드는 `crypto.randomBytes(12).toString("base64url")`, 10분)을 만들고, 봇이 개인 채팅의 `/start <코드>`가 맞고 유효할 때만 그 사용자 id를 `telegram.owner`로 저장한 뒤 파일을 지우는 것이다. 틀린 코드에는 답하지 않는다(D12). **HTTP로 코드를 발급하지 않는다.** 테일스케일 Serve를 거친 요청은 서버에 loopback처럼 보이므로(보안 점검 A-3, `docs/security/2026-10-18-phase1-code.md`) 원격 요청이 코드를 받아 갈 길이 열린다.
5. **따라가는 세션과 기본값.** 봇은 세션 하나를 따라가며 그 세션의 카드를 알리고 질문의 기준으로 삼는다. 고르지 않으면 `catalog.list` 정렬의 첫 항목(Herdr에서 열린 세션 중 최근)이다. 프로필은 config.json `telegram.profileId`(없으면 default) 하나에 묶는다. 프로필은 인증이 아니라 개인화 단위다.
6. **카드 알림은 봇의 모델 호출이 0이다(D7, D8).** 먼저 말하는 것은 카드 알림뿐이다. 본문은 사건 종류 문구와 `focus.label`(이미 100자 이하로 자른 첫 의미 줄)뿐이고, 전문은 '원문 보기' 버튼을 누를 때만 보낸다. 설명은 누를 때 한다. 미리 설명은 프로필 `autoExplain`을 그대로 따르며 한도(10분 5개)와 기본값은 바꾸지 않는다(0063). 단서: 카드를 고르는 Jev 실시간 판정은 Jev 키가 있으면 [0006](0006-live-and-memory.md), [0012](0012-refresh-and-replay.md)대로 계속 돈다. 봇 자체는 설명 모델을 부르지 않는다는 뜻이다.
7. **설명은 `asks.open` 재사용.** 봇은 설명과 저장을 새로 만들지 않고 `asks.open`, catalog, prefetch hub에 맡긴다. 같은 문답이 모든 화면에 보인다(D2, [0037](0037-mobile-terminal-and-macos.md)). 답을 만드는 동안에는 `sendMessageDraft`(개인 채팅 전용, `can_stop`)로 보여 주고, 끝나면 `sendMessage`로 확정한다. 초안 갱신은 1초에 한 번 이하다. 서식은 HTML 모드로 굵게, 코드, 인용만 바꾸고 나머지는 평문이며 "더 자세히"는 `<blockquote expandable>`이다. 봇에서 온 질문도 다른 화면과 같은 설명 경로를 쓴다.
8. **메시지와 스레드 표, 답장 이어 묻기.** 봇이 보낸 메시지 id를 `{sessionId, thread}`에 잇는 표를 둔다. 알림이나 답에 답장하면 그 스레드로 묻고, 그냥 보내면 따라가는 세션의 세션 전체 대화로 묻는다. 스레드는 서버가 발급하고 봇은 계산하지 않는다([0053](0053-conversation-list-module.md)).
9. **상태 저장과 재시작 뒤 몰아 알림.** 상태는 `DOCENT_HOME/telegram.json`에 둔다(getUpdates offset, 따라가는 세션, 보낸 카드 기록, 메시지와 스레드 표). 서버가 꺼져 있던 동안 놓친 카드는 재시작 뒤 한 번에 몰아 알린다.
10. **텔레그램 서버에 남는 내용.** 알림 첫 줄, 주인의 질문, 도슨트의 답, 누른 원문은 텔레그램 서버를 지난다. 봇 채팅은 종단 간 암호화(비밀 대화)가 아니므로 텔레그램이 보관할 수 있다. 주인이 이를 알고 쓰며, 안내 문서에 적는다.
11. **결정 기록.** 표면을 여는 이 결정은 새 ADR로 남기고 ADR 0014의 문장을 대체한다. 문서 안에서 조용히 뒤집지 않는다(D5). ADR 0014 본문은 고치지 않는다.

## 하지 않는 것

- 코드와 파일 수정, 명령 실행, 코딩 에이전트(샤를 포함)에게 메시지 보내기. 도슨트는 설명만 한다.
- 여러 사용자, 그룹, 채널.
- 디스코드, 카카오톡, Slack 어댑터.
- 샤를(`~/.dori`) 코드, 설정, 토큰 변경.

## 결과

- 이 결정은 D1부터 D12까지를 담는다. 대응은 D1은 2, D2는 7, D3은 3, D4는 1과 4, D5는 11, D6은 1, D7은 6, D8은 6, D9는 2, D10과 D11은 3, D12는 4번 항목이다.
- 보안 점검의 B-1(설명 대화의 read 도구)은 이 결정이 풀지 않는다. 봇의 질문도 다른 화면과 같은 `--tools read` 경로를 쓰고, 질문하는 사람은 주인 한 명뿐이다. B-1은 모든 화면 공통 과제로 남는다.
- 알림 첫 줄, 질문, 답, 누른 원문이 텔레그램 서버에 남는다(결정 10).
- 토큰이 없으면 봇 코드가 시작되지 않아, 기존 사용자의 동작은 그대로다. 토큰 환경변수는 운영에서 기존 비밀값 규칙(SECURITY.md)대로 1Password에서 환경변수로 넣는다.
- 새 시험은 가짜 Bot API로 module을 시험하고, 통합 시험은 가짜 텔레그램 서버를 `DOCENT_TELEGRAM_API`(기본 `https://api.telegram.org`)로 연결한다.

## 영향 범위

- 새 module: 봇(텔레그램 Bot API 호출, 서식 변환, 봇 본체)과 서버 연결.
- `docent telegram pair` 명령, `/api/bot` 상태 응답, config.json `telegram` 항목, `DOCENT_HOME/telegram.json`, `DOCENT_HOME/telegram-pair.json`.
- 문서: `CONTEXT.md`(도슨트 봇, 따라가는 세션), `AGENTS.md` 빠른 링크, README의 봇 안내.
- 바뀌지 않는 것: 설명 프롬프트(`prompt/docent.md`), 미리 설명 한도와 기본값, INSTALL-AGENT.md.
