# 0070 — 터미널 마우스는 OMP 전체 화면 모드와 Herdr의 방식을 따른다

Date: 2026-10-15
Status: Accepted. 사용자 요청. ADR 0038(터미널 화면)과 ADR 0068(선택창)에 마우스를 더한다.

## Context

`docent-tui`는 전용 화면(`ESC[?1049h`)에서 마우스 보고를 켜지 않았다. 터미널과 Herdr가 마우스를 앱에 넘기지 않아 휠, 클릭이 도슨트에 닿지 않았고, 선택창과 입력창을 마우스로 쓸 수 없었다. 사용자는 "OMP 마우스 작동방식 + Herdr 마우스 사용방식"을 요청했다.

조사한 사실:

- Pi 터미널 라이브러리(`@earendil-works/pi-tui`)의 전체 화면 모드(`TuiAltScreen`)는 SGR 마우스(`?1000h ?1002h ?1006h`)를 켠다. 휠은 보이는 영역을 스크롤하고 목록(`SelectList`)에서는 선택을 한 칸 옮긴다. 왼쪽 누름은 목록 항목을 고르고 뗄 때 확정한다(드래그 없이 눌렀다 뗀 클릭). 끌기는 앱이 글자를 고르고 `copyOnSelect`로 복사하며 두 번 눌러 낱말을 고른다. 낱말은 경로와 kebab-case를 통째로 잡는다. 일반 화면 모드(`TuiMainScreen`)는 마우스를 잡지 않고 터미널이 스크롤백을 맡는다.
- Herdr 0.9.5 문서: "mouse-native". 창, 탭, 작업 공간, 에이전트를 클릭하고, 끌어서 고르면 클립보드로 복사(`ui.copy_on_select`)하며, 두 번 눌러 낱말을 고르고, 휠은 `ui.mouse_scroll_lines`(기본 3줄)만큼 스크롤한다. 오른쪽 클릭은 Herdr 메뉴다. 마우스 보고를 켠 창의 앱에는 `ui.right_click_passthrough_modifier`를 지정했을 때만 오른쪽 클릭 계열이 넘어간다.

## Decision

1. 시작할 때 `ESC[?1000h ESC[?1002h ESC[?1006h`로 SGR 마우스 보고(누름, 뗌, 누른 채 움직임, 휠)를 켜고 종료와 중단에서 끈다(`DOCENT_MOUSE=0`이면 처음부터 켜지 않음). `/마우스 (mouse)`로 실행 중에 끄고 켠다. 끄면 터미널과 Herdr가 글자 선택과 스크롤을 다시 맡는다.
2. 휠: 선택창에서는 한 칸에 항목 하나(끝에서 멈춤, 한 칸씩 이동하는 키와 달리 돌아가지 않음), `/` 명령 목록이 열려 있으면 그 목록, 그 밖에는 대화를 한 칸에 3줄(Herdr 기본값) 스크롤하고 맨 아래에 닿으면 새 글을 다시 따라간다.
3. 왼쪽 클릭: 선택창에서는 누르면 그 항목이 골라지고 끌지 않고 떼면 연다(OMP 목록과 같음). 입력창에서는 누른 글자 앞에 커서가 간다(여러 줄, 넓은 글자, 탭 포함). 오른쪽, 가운데 단추는 앱이 쓰지 않는다.
4. 끌기: 누른 칸에서 끈 칸까지의 글자를 반전해서 보이고 놓으면 복사한다. 넓은 글자는 칸 끝에 걸쳐도 통째로 고르고 줄 끝 공백은 뺀다. 두 번 누르면 낱말(글자, 숫자와 `_ / . - ~ @`)을 골라 복사한다. 키를 누르면 고른 글자가 풀리고, 고른 글자가 있을 때 Ctrl+C는 복사만 하고 설명을 멈추지 않는다. 복사했다는 알림은 알림 줄을 늘려 화면이 밀리지 않도록 제목 줄 오른쪽에 2초 보인다.
5. 복사는 OSC 52(SSH 너머에서도 동작, 70,000자까지)와, 이 컴퓨터의 macOS(SSH 아님)에서는 `pbcopy`로 함께 한다. 시험은 `runTerminal({copy})`로 대신한다.
6. 마우스 해석은 `terminal-input.mjs`(`decodeMouse`)가 SGR 보고를 0부터 시작하는 좌표의 이벤트로 바꾸고, 글자 선택과 낱말 규칙은 상태 없는 `terminal-mouse.mjs`, 눌림 판정은 선택창이 돌려주는 항목별 줄 범위(`hits`)와 입력창의 줄 시작 글자 순번(`layoutDraft`의 `starts`)이 한다.

## Consequences

- 마우스 보고를 켜면 터미널(과 Herdr)의 글자 끌기 선택이 이 창에서는 꺼진다. 대신 앱의 선택이 같은 동작을 한다. 고른 줄은 색을 잃고 평문으로 보인다. 전체 화면 칸 기준이라 대화가 스크롤되면 고른 글자는 화면 위치에 남는다. 터미널 본래 선택이 필요하면 `/마우스`로 끈다.
- Herdr가 마우스 보고를 켠 창에 왼쪽 클릭, 끌기, 휠을 그대로 넘기는지, OSC 52를 바깥 터미널까지 넘기는지는 이 저장소에서 검증하지 못했다[INFERENCE: 문서가 "마우스 보고 앱"에 일부만 넘긴다고 적었다]. 시험은 가짜 입력으로 이벤트 처리와 복사 호출을 확인하고, 실제 pty에서 마우스 보고 켜기와 끄기, 휠과 클릭이 화면에 반영되는 것을 확인했다.
