# 0060 — 세션 목록은 Herdr에 열린 세션을 작업 공간 순서로 앞에 두고, 작업 공간 이름을 카드에 보인다

Date: 2026-10-14
Status: Accepted. ADR 0056(세션 목록)의 "최근 활동 순 200개" 정렬 규칙과 ADR 0045(세션 카드)의 카드 구성을 바꾼다. ADR 0044(`docent herdr`)의 Herdr 연동은 그대로이고, 이 결정은 목록을 읽기만 한다.

## Context

1. **목록 순서가 무작위로 보였다.** 목록은 파일의 최근 수정 시각 순이다. Herdr에서 여러 에이전트를 동시에 돌리면 모두 몇 초 간격으로 갱신되어 카드가 계속 자리를 바꾸고, 지금 보는 Herdr 작업 공간의 세션을 찾기 어렵다.
2. **카드에는 어느 작업 공간의 세션인지가 없었다.** 사용자는 Herdr 사이드바에서 작업 공간에 이름을 붙여 쓰는데(예: "워드프레스 리팩터링") 도슨트 카드는 저장소, 브랜치, 제목만 보였다. 이름을 바꿔도 반영될 곳이 없었다.
3. **필요한 정보는 Herdr가 이미 안다.** Herdr 0.9.3의 `herdr agent list`는 창마다 에이전트가 연 세션 파일의 절대 경로(`agent_session.value`, `kind: "path"`)와 창 번호(`pane_id`, 예 `w4B:p2`)를 주고, `herdr workspace list`는 작업 공간의 `workspace_id`, 사용자가 붙인 `label`, 사이드바 순서 `number`를 준다. 두 명령 모두 `{"result": …}` JSON을 출력한다.
4. **운영 서버는 Herdr 환경을 상속하지 않는다.** launchd 서버에는 `HERDR_*` 환경변수가 없고 PATH도 최소다. `env -i HOME=$HOME ~/.local/bin/herdr workspace list`가 동작하는 것을 확인했다(PATH에서 못 찾으면 이 경로로 넘어간다).

## Decision

1. **`app/herdr-workspaces.mjs`가 두 명령을 읽어 세션 파일 경로 → `{ workspace, label, number, pane }`로 바꾼다.** `workspace`는 `pane_id`의 `:` 앞부분, `pane`은 `pane_id` 그대로다. `agent_session.kind`가 `path`가 아닌 창, 작업 공간 목록에 없는 창은 건너뛴다. 이름이 비어 있으면 `작업 공간 <번호>`로 보인다. 같은 세션이 두 창에 열려 있으면 번호가 앞선 쪽을 쓴다.
2. **실행은 PATH의 `herdr`, 없으면 `~/.local/bin/herdr`다.** `HERDR_*` 환경변수에 기대지 않는다. 명령마다 1.5초 안에 끝나지 않으면 끊는다. herdr가 없거나, 실패하거나, JSON이 아니거나, 두 명령 중 하나라도 실패하면 정보 없음(빈 Map)으로 두고 목록은 예전 그대로 나간다. 오류를 사용자에게 보이지 않는다.
3. **결과는 3초 동안 기억한다.** 실패한 결과도 3초 기억해 herdr가 멈춘 환경에서 목록을 부를 때마다 1.5초씩 기다리지 않게 한다. 같은 시각에 부른 쪽은 하나의 조회를 함께 기다린다. Herdr에서 작업 공간 이름을 바꾸면 다음 목록 새로고침(웹은 15초마다)에서 새 이름이 보인다. 시계와 실행기는 주입할 수 있어 시험이 시간을 직접 움직인다.
4. **이 컴퓨터의 세션 제공자가 목록 항목에 `herdr: { workspace, label, number, pane }`을 붙인다.** 세션 파일의 `resolve`한 절대 경로가 위 Map에 있을 때만 붙인다. `localProviders(adapters, { home, herdr })`로 받으며 주지 않으면 붙이지 않는다. 다른 컴퓨터(peer)의 세션은 그쪽 서버가 보낸 `herdr` 필드를 그대로 둔다. 다시 계산하지 않는다(그쪽 경로를 이 컴퓨터의 Herdr가 알 수 없다).
5. **정렬 규칙(사용자 결정).** 합친 목록은 다음 순서다.
   1. 이 컴퓨터의 Herdr에 열린 세션: 작업 공간 `number` 오름차순, 같은 작업 공간에서는 창 번호(`wXX:pN`의 N) 오름차순, 같은 창이면 최근 활동이 먼저.
   2. 다른 컴퓨터의 Herdr 세션: 제공자 순서대로 컴퓨터별로 묶고, 각 묶음 안에서 1과 같은 규칙. peer의 `number`는 그 컴퓨터의 사이드바 번호라 이 컴퓨터의 번호와 비교하지 않는다. 그래서 이 컴퓨터의 Herdr 세션 뒤에 컴퓨터별로 모은다. 웹의 컴퓨터별 탭에서는 그 컴퓨터의 Herdr 세션이 맨 앞이다. `number`가 숫자가 아닌 `herdr` 필드는 Herdr 세션으로 치지 않는다.
   3. 나머지 모든 세션: 지금처럼 최근 활동 순.
   정렬은 200개로 자르기 전에 한다. Herdr에 열린 세션은 최근 200개 밖이어도 목록에서 밀려나지 않는다.
6. **웹과 터미널 카드가 작업 공간 이름을 보인다.** 웹 세션 카드는 메타 줄 맨 앞에 이름을 쓰고(마우스를 올리면 `Herdr 작업 공간 <번호>, 창 <pane>`), 검색에서 이름으로 찾을 수 있으며, 세션 정보에도 한 줄 더한다. 터미널 카드는 📦(저장소) 옆에 🔖와 이름을 쓰고(`ascii` 기호 모드는 `ws:`), `@` 목록에서도 이름으로 걸러진다. PiP와 모바일은 같은 세션 카드를 쓰므로 따로 고칠 곳이 없다.

## Consequences

- 같은 Herdr 작업 공간의 에이전트들이 목록 맨 위에 모이고, 위치가 사이드바 번호와 창 번호로 고정되어 갱신 때문에 카드가 뛰지 않는다. 같은 창의 세션이 새로 시작되면 그 창의 칸이 새 세션으로 바뀐다.
- Herdr를 쓰지 않는 사용자, 다른 터미널 멀티플렉서만 쓰는 사용자, Windows 사용자는 예전과 같은 순서이고 카드도 같다.
- 목록 요청마다 최대 3초에 한 번 `herdr` 프로세스 두 개가 뜬다. herdr가 멈춰 있으면 목록이 최대 1.5초 늦어질 수 있고 그 뒤 3초 동안은 기다리지 않는다.
- 창 번호(`pN`)는 Herdr가 창을 만든 순서이며 화면 배치 순서와 다를 수 있다. 사용자가 정한 "창 번호 순"을 그대로 따른다.
