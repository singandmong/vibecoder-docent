# 0074 — 로컬 API 본문 형식과 다른 컴퓨터 응답 검증

Date: 2026-10-18
Status: Accepted

## 문제

2026-10-18 보안 점검(1차 코드, 2차 모의공격: `docs/security/`)에서 두 가지가 확인됐다.

1. 서버가 본문의 `Content-Type` 을 보지 않고 `JSON.parse` 만 했다. 브라우저가 프리플라이트 없이 보낼 수 있는 `text/plain` 으로도 모든 POST 가 처리됐다. 그래서 사용자가 다른 사이트의 페이지를 여는 것만으로 즐겨찾기·프로필 생성, 테일스케일 공유 켜기(설정에 남아 유지), 설명 요청(모델 호출, 답이 기록에 저장)까지 됐다. CORS 헤더가 없어 응답은 읽히지 않지만 부작용은 그대로 생긴다.
2. 다른 컴퓨터(peer) 서버의 응답을 그대로 믿었다. 302 를 따라가 다른 주소를 부르고(우리 서버가 통로가 됨), 크기 제한 없이 본문을 읽고(50MB 전사에서 RSS 95MB → 319MB), 문자열이 아닌 필드가 목록을 타고 화면까지 가서 검색 한 번에 목록이 멈췄다(`TypeError: value?.toLowerCase is not a function`).

## 결정

1. **본문은 JSON 만.** 본문을 읽는 API(`POST`, `PATCH`)는 `Content-Type: application/json`(파라미터 허용)만 받고, 아니면 415 로 거절한다. 웹·터미널·CLI 는 모두 JSON 으로 보낸다. 프리플라이트 없이 보낼 수 있는 형식을 열어 두면 CSRF 가 성립하기 때문이다.
2. **peer 응답은 그대로 믿지 않는다.** 리디렉트를 따라가지 않고(`redirect: "manual"`, 다른 주소면 오류), 크기를 제한하고(목록 4MB, 전사 80MB = 이 컴퓨터 세션 파일 상한 `MAX_SESSION_BYTES`, 원격 SSE 한 프레임 1MB), 목록 항목은 우리 화면·정렬이 쓰는 필드만 맞는 형식일 때만 남긴다. 그쪽이 보낸 `host`·`ssh` 는 쓰지 않는다(기존 규칙 유지).
3. **화면은 값을 문자열로 좁혀 쓴다.** 세션 제목·최근 작업 등에 문자열이 아닌 값이 와도 목록이 멈추지 않게 `String(value ?? "")` 로 비교한다.

## 결과

- 이 결정으로 닫히지 않는 발견(별도 결정 필요): Host 검사로 DNS 재바인딩 읽기 막기, Origin 확인, 모델 호출·SSE 동시 수 상한. 모바일 PWA 가 테일스케일 Serve 를 거치는 흐름과 겹쳐 별도 검토가 필요하다.
- 시험: `tests/peers.test.mjs`, `tests/server-guards.test.mjs`. 전체 `node --test` 219개 통과.
- 확인: 개발계 인스턴스(임시 HOME, 가짜 omp)에서 같은 공격을 다시 실행해 415 와 부작용 없음, peer 리디렉트 미추적, 웹 화면 오류 없음, 터미널 질문·답 정상을 확인했다.
