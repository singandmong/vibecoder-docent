# 0055 — 설명 요청의 화면 쪽 상태는 session-client.mjs 한 module이 맡고, 웹과 터미널은 같은 transport adapter로 서버와 주고받는다

Date: 2026-10-12
Status: Accepted. 구조 점검 후보 5. ADR 0029(대기 질문, 중단, 바로잡기, 다시 붙기)와 ADR 0038 §7·§8(터미널 입력창과 초안)을 한 규칙으로 구현한다.

## Context

1. 진행 중인 설명(대기 → 단계 → 글 조각, 다시 시작, 바로잡기 → 답·실패·중단), 같은 requestId로 다시 붙기, 중단, 바로잡기, 대기 질문, 중단한 질문 되돌리기를 웹(`index.html`의 `runJob`, `reattachJobs`, `pendingQueue`)과 터미널(`terminal-ui.mjs`의 `consumeAsk`, `restoreJob`)이 따로 구현했고, 둘이 이미 달라져 있었다.
2. 서버는 다시 붙은 요청에 그때까지 쌓인 글을 `delta` 하나로 다시 보낸다. 웹은 새로고침 뒤 다시 붙을 때 `/api/jobs`의 글(`text`)을 먼저 채운 뒤 다시 받은 글을 이어 붙여, 설명이 끝날 때까지 같은 글이 두 번 보였다.
3. 웹은 `/api/ask`가 실패 상태(400, 409 등)로 답하면 서버가 준 오류 문구를 읽지 않고 "요청에 실패했어요 (409)."만 보였다(쓰이지 않는 `cancelled` 변수). 마지막 NDJSON 줄에 줄바꿈이 없으면 그 줄도 버렸다.
4. ADR 0029 §4는 설명 중 Enter를 대기 질문으로 정했지만 터미널은 "진행 중이에요"로 거절했다. 터미널은 다시 붙을 때 사용자 질문 첫 작업만 보고 서버가 준 스레드(`thread`)와 표시 이름(`display`)을 버렸다. 웹은 다시 붙을 때 바로 질문의 설명 깊이(`difficulty`)를 빼고 보내 서버가 다른 요청으로 보고 409를 줄 수 있었다.
5. 서버와 주고받는 코드(오류 문구 읽기, SSE와 NDJSON 줄 읽기)는 터미널의 `TerminalClient`에만 있었고, 웹은 `api()`, `runJob`의 `fetch`, `EventSource`로 따로 했다.

## Decision

1. **`app/session-client.mjs`가 한 세션의 설명 요청 상태를 맡는다.** interface는 `createSessionClient({ transport, drafts, cards, newRequestId, onChange })` → `open`, `close`, `ask`, `unqueue`, `stop`, `steer`, `rejoin`, `attachAuto`, `resume`, `abandon`, `follow`와 읽기 전용 `active`, `queue`, `manual`, `autoJob`이다. 바뀔 때마다 `onChange`로 `job`, `end`, `queue`, `live`, `live-status`를 알린다. 웹과 터미널은 이 알림을 받아 그리기만 한다. 대화 목록과 스레드 소속은 계속 `conversations.mjs`가 정한다.
2. **다시 붙기.** 같은 requestId로 붙을 때마다 받은 글을 비우고 시작한다. 서버가 다시 보내는 `delta` 하나가 그때까지의 글 전체다. `rejoin()`은 `/api/jobs`의 작업을 모두 따라간다. 사용자 질문의 첫 작업이 진행 중인 설명이고, 그 뒤 사용자 질문은 지켜보기만 하며(중단, 바로잡기, 입력창 복원 없음), 미리 설명도 따라간다. 요청 본문은 서버가 준 질문, 질문 대상, 미리 설명 여부, 설명 깊이로 다시 만든다. 터미널은 다시 붙은 설명의 스레드(서버가 준 값)로 간다.
3. **대기 질문.** 진행 중인 설명이 있으면 `ask()`는 대기 질문을 쌓고, 설명이 끝나면(답, 실패, 중단) 들어온 순서대로 하나씩 보낸다. 다른 세션이나 프로필로 가면(`open`, `close`) 그 대기 질문은 보내지 않는다. 세션이나 프로필을 바꾸면 그때까지의 설명 스트림은 놓고(서버 작업은 계속), 돌아오면 `rejoin()`으로 다시 붙는다.
4. **연결이 끊기면.** HTTP 상태가 없는 실패(연결 끊김, 결과 전에 닫힘)는 중단이 아니다(ADR 0029 §2). 사용자 질문은 `disconnected`로 진행 중인 설명에 남아 Enter는 계속 대기 질문이 되고, `resume()`으로 같은 요청에 다시 붙는다. `abandon()`은 그 설명을 더 따라가지 않고 다음 대기 질문으로 넘어간다. 미리 설명은 실패로 끝난다. HTTP 상태가 있는 실패는 서버 문구와 상태를 결과(`error`, `status`)로 낸다.
5. **중단한 질문 되돌리기.** 서버가 중단을 받아들이면 보낸 질문은 그 질문의 자리(프로필, 세션, 서버가 준 스레드)의 입력창이 비어 있을 때만 돌아간다. 보내지 못한 대기 질문도 같은 규칙이다. 입력창은 `drafts.read/write` port로 받는다. 터미널은 ADR 0038 §8의 자리별 초안을 그대로 쓰고, 돌려놓지 못한 대기 질문은 그 수와 문장을 입력창 위에 알린다. 웹은 지금 세션과 프로필의 입력창 하나만 쓴다(웹의 한 입력창 방식은 바꾸지 않는다). 그래서 웹은 세션이나 프로필을 바꿀 때 `close()` 전에 대기 질문을 `unqueue`로 버리고 입력창으로 돌려놓지 않는다. 이 결정 전 웹과 같은 동작이고, 새 세션의 입력창에 다른 세션의 질문이 들어가지 않게 한다.
6. **transport adapter는 하나다.** `TerminalClient`를 `app/transport.mjs`의 `HttpTransport`로 옮겨 웹과 터미널이 같이 쓴다. `fetch`, `ReadableStream`, `TextDecoder`만 쓰고(`fetchImpl` 바꿔 끼우기), 서버의 `{error}` 문구와 HTTP 상태를 `TransportError`에 싣는다. 마지막 줄에 줄바꿈이 없어도 읽는다. 터미널 제어 문자 제거와 "(HTTP 409)" 덧붙이기는 터미널 화면이 한다. 실시간 사건은 `follow()`가 SSE로 받고 닫히거나 실패하면 0.5초부터 8초까지 늘려 다시 붙는다.
7. 두 module은 `node:` module을 쓰지 않는다. 웹은 `/transport.mjs`, `/session-client.mjs` 정적 파일로 불러온다(`conversations.mjs`와 같은 방식, 빌드 없음).
8. **터미널의 대기 질문 화면.** 대기 질문은 진행 중인 설명 아래에 "대기 질문 1  …"로 보인다. `/대기 (queue)` 명령은 마지막 대기 질문을 그 스레드의 입력창에 돌려놓아 고치거나 지우게 한다(ADR 0029 §4의 고치기, 지우기).

## Consequences

- 새로고침 뒤 진행 중인 설명의 글이 한 번만 보인다. 웹의 질문 실패에 서버가 준 이유가 보인다.
- 터미널에서 설명 중 Enter가 대기 질문이 되어 설명이 끝나면 보내진다. 연결이 끊긴 동안 친 질문도 대기 질문이 되고 Ctrl+R로 다시 붙은 설명이 끝난 뒤 나간다.
- 웹에서 연결이 끊긴 설명은 실패 상자를 보이되 진행 중인 설명으로 남는다. 실패 상자는 스레드를 다시 그리거나 다른 스레드에서 돌아와도 그 질문 아래에 다시 보인다(작은 창에는 실패 문구만). 중단 버튼이 그대로 있고, 새 질문은 "같은 요청 결과 다시 확인"이나 "새 설명 요청"을 누를 때까지 대기 질문이 된다. 중단했는데 서버에 그 설명이 없으면(이미 끝났거나 서버가 다시 시작됨) 끊긴 설명은 `abandon()`으로 놓고 다음 대기 질문으로 넘어가며 그 사실을 알린다. 전에는 끊기면 바로 새 질문을 보냈다.
- 터미널에서 세션이나 프로필을 바꾸면 그 설명을 화면에서 놓는다. 다른 세션에서 바로 질문할 수 있고, 돌아오면 다시 붙는다. 전에는 다른 세션의 설명이 끝날 때까지 질문을 거절했다.
- 웹의 실시간 연결은 `EventSource` 대신 같은 SSE 읽기를 쓰고, 끊김 알림 없이 다시 붙는다(전과 같음). 읽지 못한 실시간 줄은 조용히 건너뛴다.
- 터미널 오류 문구에서 서버 거절(HTTP 상태 있음)은 "설명을 만들지 못했어요: …"로 보인다. 전에는 "설명 요청에 실패했어요: … (HTTP 409)"였다.
- 영향 범위: `app/session-client.mjs`(신규), `app/transport.mjs`(`app/terminal-client.mjs`에서 옮김), `app/terminal-ui.mjs`, `app/index.html`, `app/server.mjs`(정적 파일 목록), `tests/session-client.test.mjs`(신규), `tests/terminal.test.mjs`, `docs/architecture.md`, `README.md`.
