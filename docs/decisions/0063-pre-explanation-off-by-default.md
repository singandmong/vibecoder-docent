# 0063 — 새 프로필의 미리 설명은 꺼진 채 시작한다

Date: 2026-10-14
Status: Accepted. ADR 0031(서버 미리 설명)의 "프로필 기본값은 켜짐"을 바꾼다. 미리 설명의 차례, 한도, 지켜보는 시간은 그대로다.

## Context

- 미리 설명은 새 질문, 작업 결과, 계획 카드마다 모델을 부른다. 설치하자마자 켜져 있으면 사용자가 아무것도 묻지 않았는데 세션을 한 번 연 것만으로 모델 호출 비용이 생긴다.
- 기본 프로필(`default`)은 `learning.json`이 없을 때 만들어지고, 새 프로필은 설정 화면이나 `POST /api/profiles`로 만든다. 둘 다 `autoExplain: true`로 시작했다.
- 0.24 전에 저장된 프로필은 값이 이미 파일에 있거나(켜짐 또는 끔), 이 필드가 생기기 전에 만든 프로필처럼 필드가 없으면 읽을 때 켜짐으로 채웠다. 사용자는 지금 쓰는 값을 바꾸지 말라고 했다.

## Decision

1. **설치 직후의 기본 프로필과 새로 만드는 프로필은 `autoExplain: false`다.** `app/store.mjs`의 빈 상태와 `app/learning.mjs`의 `createProfile`이 같은 값을 쓴다.
2. **저장된 프로필은 바꾸지 않는다.** 파일에 적힌 값은 그대로 읽는다. `autoExplain`이 없는 프로필은 그것이 만들어진 때의 기본값(켜짐)으로 채운다. 이 둘은 0.24 전과 같다.
3. 켜는 방법은 그대로다. 웹 설정의 "새 주요 내용 자동 설명", 터미널 `$` 설정의 "미리 설명 켜기", `PATCH /api/profiles/<id>`의 `{"autoExplain": true}`.

## Consequences

- 새 사용자는 직접 묻기 전에는 모델 호출 비용이 생기지 않는다. 미리 설명을 원하면 한 번 켜야 한다. 설정 화면의 "현재 상태: 꺼짐"이 그 상태를 보여 준다.
- 기존 설치의 프로필은 켜짐이면 켜짐, 끔이면 끔으로 남는다. 업데이트 뒤 동작이 바뀌지 않는다.
- 시험: 빈 `DOCENT_HOME`의 기본 프로필과 새 프로필이 꺼진 채 시작하는지(`tests/learning.test.mjs`), 필드 없는 옛 프로필이 켜진 채 미리 설명하는지(`tests/ask.test.mjs`) 확인한다.
